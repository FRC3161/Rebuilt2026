01 How this happened

What started as a full source audit turned into a diagnosis, then a rewrite, once the team's own field observation — "we undershoot while moving" — pointed at a specific formula.

→
Full audit.

Read every subsystem end to end. Found roughly a dozen correctness bugs — dead homing thresholds, config applies aliased to the wrong motor, an auto-pathfind end condition that never updated — plus a long list of unreachable states and dead files.

→
Diagnosis.

The team reported undershooting while driving. Turret aim tracked correctly, but flywheel speed sagged with closing speed — the signature of an error that lives entirely on the radial axis. Traced to ShotCalc applying the same velocity correction three times.

→
Visualization audit.

The sim's ball-trajectory view — built to check exactly this — turned out not to draw the commanded shot at all, and disagreed with itself on flight time. Audited and rebuilt alongside the fix so it can actually verify the fix.

→
Rewrite + review.

Full rewrite on a dedicated branch, verified against a Gradle build, then put through an 8-angle automated code review. Two review findings are still open — see §04.

03 What changed, subsystem by subsystem

Summary only — see the branch diff for line-level detail. Every PID gain, shot-map entry, current limit, and motor ID was carried over unchanged.

Fixed
Shoot-on-the-fly math — ShotCalc.java

The undershoot-while-moving bug above. See §02.

Fixed
Intake extension control — Intake.java

Manual nudge and the homing crawl were silently overridden every 20 ms by a leftover position command in the same loop — split into explicit position-vs-duty-cycle control modes. Also fixed a config mix-up where leaving the slow-squeeze (SCORE) state applied the roller's untuned config to the extension motor, wiping its PID gains.

Fixed
Shooter readiness & homing — Shooter.java

A static "is shooting" flag that was never updated made the feeder's ready-to-shoot check always read stale. The hood's current-based homing threshold defaulted to zero, which would have instantly re-zeroed the hood on every boot; now gated off until tuned.

Fixed
Turret aim trim & limits — Turret.java

The driver's aim-trim offset was applied after the soft-limit wrap, so repeated nudges could walk the target past the mechanical limit; now applied before, then clamped. A feedforward term that fed rad/s into a volts-only control input was removed rather than fixed — flagged as an open item, §04.

Fixed
Autonomous pathfinding — DriveToLocation.java

Acceleration and angular-speed pathfinding constraints were left at Java's default of 0.0, and the "close enough" check computed a single unsigned error once at command creation instead of re-checking every loop — auto pathfind commands could cancel on the very first tick.

Fixed
Vision frame handling — Vision.java

Camera frames were pulled with a "latest result" call that can hand back the same frame twice or skip one; switched to reading every unread frame exactly once, and ambiguity rejection is now only applied where it's statistically meaningful (single-tag solves).

Behavior change
Battery eco-mode & match timer — RobotContainer.java

The automatic low-battery trigger compared "now" to "now, four seconds from now" in the same instant and could never fire; fixed the debounce and wired it up. The match timer now restarts every time teleop is entered instead of never resetting. Both changes are correct in the common case; the code review surfaced edge cases worth a second look — §04.

Removed
Dead code — 10 files

Two abandoned rewrites of the shot-calc and vision code, an unbound test command that drove a motor at −100% duty with no way to stop it, and five aiming/interpolation utility classes whose only callers were the code being deleted. All fully superseded by the tuned lookup tables already in Constants.java.

04 Before this goes on the robot

The branch builds clean and hasn't been proven wrong — but it also hasn't been run yet. These are the open items, roughly in the order they'd bite.

Not yet verified

Test the SOTF fix in sim

Drive at the hub with driver2's trigger held and watch the commanded RPS on the dashboard hold steady instead of sagging as speed increases.

Data quality

Validate the flight-time table

TOF_MAP implies ball speeds several times faster than the flywheel's own launch-speed model suggests. It feeds directly into the SOTF lead distance, so an error here re-introduces under- or over-shoot from a different direction.

Code review finding

Re-check the automatic eco-mode trigger

It now chains six blocking motor-config calls unattended, right as the battery is already sagging — likely during a high-current endgame push. Worth staggering the calls or keeping it manual-only.

Code review finding

Confirm match-timer behavior on re-enable

Restarting the timer on every teleop entry fixes stale elapsed time on a normal match, but zeroes it again on a mid-match disable/re-enable — trading one direction of error for the other.

Code review finding

Restore turret rotation compensation

The removed feedforward term likely contributed real tracking lag while turning during a shot. Worth reintroducing with the correct unit conversion rather than leaving it out.

Preserved, unchanged

Intake re-zero workflow is still manual

D-pad nudge into the hard stop, then the driver's back button — unchanged and confirmed intentional. The CANrange auto-zero path stays disabled until someone wants to wire it up.
